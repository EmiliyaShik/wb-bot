## 2. Самое важное следствие: нужна категория «Финансы»

Отчёт о реализации переехал со `statistics-api` на **`finance-api`**, а это **другая категория токена**. В ТЗ перечислены Статистика, Аналитика, Продвижение, Контент. Без категории **Финансы** модуль `finance` (агенты 1, 2, 3) не работает вообще.

Проверенное соответствие «что нужно для чего»:

| Что делает бот | Хост | Категория токена |
|---|---|---|
| Отчёт о реализации (агенты 1, 2, 3) | `finance-api.wildberries.ru` | **Финансы** |
| Воронка продаж, остатки, лента заказов (агент 4) | `seller-analytics-api.wildberries.ru` | **Аналитика** |
| Расход рекламы (агенты 3, 4) | `advert-api.wildberries.ru` | **Продвижение** |
| Список карточек для шаблона себестоимости | `content-api.wildberries.ru` | **Контент** |
| Информация о продавце | `common-api.wildberries.ru` | любая |

Категория **Статистика** в текущей сборке не нужна ни для чего: единственные оставшиеся там методы (`orders`, `sales`) объявлены к отключению, а их замена живёт в Аналитике.

## 3. Авторизация и токен

**Заголовок:** `Authorization: <токен>` - **без** `Bearer`. Префикс `Bearer` относится к другому API (WBD), не к Seller API.

**Токен - валидный JWT, срок жизни 180 дней.** Payload читается без единого сетевого запроса.

Документированные поля payload:

| Поле | Тип | Что значит |
|---|---|---|
| `id` | UUIDv4 | ID самого токена |
| `sid` | UUIDv4 | **ID продавца на Wildberries** |
| `exp` | uint | Unix-время истечения |
| `s` | uint | Битовая маска свойств |
| `acc` | int | Тип: `1` Базовый, `2` Тестовый, `3` Персональный, `4` Сервисный |
| `for` | string | `self` у Персонального; `asid:{ID}` у Сервисного |
| `t` | bool | `true` - тестовый токен (песочница) |
| `iat` | uint | Время выпуска. Служебное, для проверок использовать нельзя |

**НЕ ПОДТВЕРЖДЕНО:** полей `oid`, `sandbox`, `uid` в документации нет. Признак песочницы называется `t`. Числового ID продавца в токене нет, только UUID `sid`.

**Маска `s`.** Бит считается от 0 (младший). Проверка: `s & (1 << бит) != 0`.

| Бит | Категория |
|---|---|
| 1 | Контент |
| 2 | Аналитика |
| 3 | Цены и скидки |
| 4 | Маркетплейс |
| 5 | Статистика |
| 6 | Продвижение |
| 7 | Вопросы и отзывы |
| 9 | Чат с покупателями |
| 10 | Поставки |
| 11 | Возвраты покупателями |
| 12 | Документы |
| 13 | **Финансы** |
| 16 | Пользователи |
| **30** | **Только на чтение (read-only)** |

Биты 0, 8, 14, 15 - **НЕ ПОДТВЕРЖДЕНО**, в официальной таблице их нет.

Отдельной категории «Рекомендации» нет (это часть Контента). «Покупатели» тоже нет: есть «Чат с покупателями» (9) и «Возвраты покупателями» (11).

Итог для проверки токена: из одного JWT без сети читаются срок (`exp`), ID кабинета (`sid`), признак «только на чтение» (бит 30), тип токена (`acc == 3` - персональный) и полный набор категорий.

## 4. Проверка связи: `/ping`

`GET https://<host>/ping` есть у каждого домена. Ответ 200: `{"TS": "...", "Status": "OK"}`. Работает с токеном любой категории. Проверяет доставку запроса, валидность токена и совпадение категории токена с сервисом. **Не** проверяет работоспособность самого сервиса.

**Лимит: максимум 3 запроса за 30 секунд, отдельно на каждый домен.** В документации прямо сказано: при попытке автоматизировать использование метода запросы будут временно заблокированы. Значит `/diag` запускается только вручную, никогда по расписанию, и между хостами делает паузу.

Нужные хосты: `finance-api`, `seller-analytics-api`, `advert-api`, `content-api`, `common-api`, `statistics-api`.

**Информация о продавце:** `GET https://common-api.wildberries.ru/api/v1/seller-info`, токен любой категории. Ответ: `name`, `sid`, `tin` (ИНН), `tradeMark`. Лимит: 1 запрос в минуту, всплеск 10.

## 5. Отчёт о реализации (агенты 1, 2, 3)

Хост `https://finance-api.wildberries.ru`, категория **Финансы**, доступно по Персональному и Сервисному токену. Данные - **с 29 января 2024 года**.

| Метод | Путь |
|---|---|
| Список отчётов (готовые агрегаты) | `POST /api/finance/v1/sales-reports/list` |
| Детализация за период | `POST /api/finance/v1/sales-reports/detailed` |
| Детализация по ID отчёта | `POST /api/finance/v1/sales-reports/detailed/{reportId}` |
| Эквайринг: детализация | `POST /api/finance/v1/acquiring/detailed` |
| Баланс | `GET /api/v1/account/balance` |

**Тело `sales-reports/detailed`:** `dateFrom`, `dateTo` (RFC3339), `limit`, `rrdId` (пагинация: начать с `0`, дальше подставлять `rrdId` последней строки), `period` (`weekly` по умолчанию / `daily`), `fields` (список нужных полей; если не задан - все).

Параметров `diviser` и `remainder` в текущем API **нет**.

**Лимит: 1 запрос в минуту** (Персональный, Сервисный). Всплеск 1. Это самый жёсткий лимит в проекте.

Максимальная длина периода за один запрос - **НЕ ПОДТВЕРЖДЕНО**, в описании метода не указана. Пагинация через `rrdId` есть, значит выгрузка года идёт страницами, а не одним куском.

### Поля ответа, которые нужны боту

Имена в camelCase. Старые snake_case из отключённого v5 больше не существуют.

| Поле | Что значит |
|---|---|
| `reportId` | ID отчёта (недели) |
| `rrdId` | ID строки, он же курсор пагинации |
| `dateFrom`, `dateTo` | начало и конец отчётного периода |
| `rrDate` | дата операции |
| `nmId` | артикул WB |
| `vendorCode` | артикул продавца |
| `subjectName` | предмет |
| `docTypeName` | тип документа (продажа, возврат) |
| `sellerOperName` | обоснование для оплаты |
| `quantity` | количество |
| `retailPrice` | цена розничная |
| `retailAmount` | Wildberries реализовал товар |
| `retailPriceWithDisc` | цена розничная с учётом согласованной скидки |
| `salePercent` | согласованный продуктовый дисконт, % |
| `spp` | **платформенные скидки, % - это и есть СПП** |
| `commissionPercent` | размер кВВ, % |
| `kvwBase` | размер кВВ без НДС, % - базовый |
| `kvw` | итоговый кВВ без НДС, % |
| `supRatingUp` | снижение кВВ из-за рейтинга, % |
| `isKgvpV2` | снижение кВВ из-за акции, % |
| `vw` | вознаграждение Wildberries, без НДС |
| `vwNds` | НДС с вознаграждения Wildberries |
| `ppvzSalesCommission` | вознаграждение с продаж до вычета услуг поверенного, без НДС |
| `ppvzReward` | возмещение за выдачу и возврат на ПВЗ |
| `forPay` | **к перечислению продавцу за реализованный товар** |
| `acquiringFee` | компенсация платёжных услуг (эквайринг, ₽) |
| `acquiringPercent` | **размер компенсации платёжных услуг, %** |
| `acquiringBank` | банк-эквайер |
| `deliveryAmount`, `returnAmount` | количество доставок и возвратов |
| `deliveryService` | услуги по доставке товара покупателю (логистика, ₽) |
| `rebillLogisticCost` | возмещение издержек по перемещению и обработке |
| `paidStorage` | хранение |
| `paidAcceptance` | операции на приёмке |
| `penalty` | общая сумма штрафов |
| `additionalPayment` | корректировка вознаграждения WB |
| `deduction` | удержания (сюда попадает и реклама) |
| `warehouseLogisticsCoeff` | коэффициент доставки |

Числовые суммы приходят строками (`type: string`) - парсить аккуратно.

### Агрегаты по отчёту: `sales-reports/list`

Возвращает уже посчитанные суммы, лимит тоже 1 запрос в минуту:
`reportId`, `dateFrom`, `dateTo`, `retailAmountSum`, `forPaySum`, `avgSalePercent`, `deliveryServiceSum`, `paidStorageSum`, `paidAcceptanceSum`, `deductionSum`, `penaltySum`, `additionalPaymentSum`, `bankPaymentSum`, cashback-суммы.

**Это то, чем проверяется совпадение с кабинетом WB** (R165): бот считает неделю по строкам и сверяет с агрегатом из `list`. Расхождение - повод показать предупреждение, а не молча отдать свою цифру.

### Формулы

**В документации WB формул нет.** У всех четырёх ключевых величин есть **готовые поля**, и правильнее брать их, а не пересчитывать:

| Величина | Откуда брать | Проверочная формула |
|---|---|---|
| К перечислению | `forPay` по строке, `forPaySum` по отчёту, `bankPaymentSum` - итог на счёт | - |
| Фактическая комиссия, % | `commissionPercent`, итоговая `kvw` | `vw / retailPriceWithDisc * 100` |
| Эквайринг, % | `acquiringPercent` | `acquiringFee / retailPriceWithDisc * 100` |
| СПП, % | `spp` | - |

Доля логистики = `сумма deliveryService / сумма retailAmount * 100`. Доля хранения = `сумма paidStorage / сумма retailAmount * 100`. Это уже наши определения, не из документации, и их надо назвать на листе «Методология».

## 6. Реклама (агенты 3, 4)

Хост `https://advert-api.wildberries.ru`, категория **Продвижение**.

**`GET /adv/v1/promotion/count`** - список кампаний. Параметров нет. Ответ: `adverts[].type`, `.status`, `.count`, `.advert_list[].advertId`, `.advert_list[].changeTime`, `all`. Лимит: 5 запросов в секунду, всплеск 5.

**`GET /adv/v3/fullstats`** - статистика. Метод **GET**, не POST. Все параметры обязательны и идут в query:
- `ids` - ID кампаний, **максимум 50 за раз**
- `beginDate`, `endDate` - **максимум 31 день** за запрос

Лимит: **3 запроса в минуту**, интервал 20 секунд, всплеск 1.

Структура ответа (расход по артикулу и по дням есть):

```
[].advertId, views, clicks, ctr, cpc, cr, atbs, orders, shks, sum, sum_price, canceled, currency
[].boosterStats[]: avg_position, date, nm          <- тут артикул называется nm
[].days[]: date, views, clicks, ctr, cpc, cr, atbs, orders, shks, sum, sum_price, canceled
[].days[].apps[]: appType (1 сайт, 32 Android, 64 iOS), + те же метрики
[].days[].apps[].nms[]: nmId, name, views, clicks, ctr, cpc, cr, atbs, orders, shks, sum, sum_price, canceled
```

Расход на артикул за день = `days[].apps[].nms[].sum`, суммировать по `apps`. Артикул здесь называется **`nmId`**; имя `nm` встречается только в `boosterStats`.

С июля 2026 суммы в валюте аккаунта продавца, есть поле `currency`.

## 7. Воронка продаж (агент 4)

Хост `https://seller-analytics-api.wildberries.ru`, категория **Аналитика**, все методы **POST**.

| Метод | Путь |
|---|---|
| За период | `POST /api/analytics/v3/sales-funnel/products` |
| По дням | `POST /api/analytics/v3/sales-funnel/products/history` |
| По группам, по дням | `POST /api/analytics/v3/sales-funnel/grouped/history` |

**`/products`** - тело: `selectedPeriod{start,end}`, `pastPeriod{start,end}`, `nmIds[]`, `brandNames[]`, `subjectIds[]`, `tagIds[]`, `skipDeletedNm`, `orderBy{field,mode}`, `limit`, `offset`. Максимум за последние **365 дней**, данные обновляются **раз в час**. Выкупы, отмены и возвраты относятся к дате **заказа**, а не события.

Ответ:
```
data.products[].product: nmId, title, vendorCode, brandName, subjectId, subjectName,
                         productRating, feedbackRating, stocks{wb, mp, balanceSum}
data.products[].statistic.selected / .past:
    openCount, cartCount, orderCount, orderSum, buyoutCount, buyoutSum,
    cancelCount, cancelSum, avgPrice, avgOrdersCountPerDay, shareOrderPercent,
    localizationPercent,
    conversions{addToCartPercent, cartToOrderPercent, buyoutPercent}
data.products[].statistic.comparison: ...Dynamic по каждому показателю
```

**`/products/history`** - тело: `selectedPeriod{start,end}`, `nmIds[]`, `skipDeletedNm`, `aggregationLevel` (`day`/`week`). Ограничение: **максимум за последнюю неделю**. Для длинных периодов - «Аналитика продавца CSV», тип `DETAIL_HISTORY_REPORT`, но он **требует подписку Джем**.

Поля `history[]`: `date`, `openCount`, `cartCount`, `orderCount`, `orderSum`, `buyoutCount`, `buyoutSum`, `buyoutPercent`, `addToCartConversion`, `cartToOrderConversion`, `addToWishlistCount`.

**Лимит обоих: 3 запроса в минуту**, интервал 20 секунд, всплеск 3.

Соответствие старых имён (реконструкция по смыслу, официальной таблицы миграции нет):
`openCardCount → openCount`, `addToCartCount → cartCount`, `ordersCount → orderCount`, `ordersSumRub → orderSum`, `buyoutsCount → buyoutCount`, `addToCartPercent → conversions.addToCartPercent`, `cartToOrderPercent → conversions.cartToOrderPercent`, `buyoutsPercent → conversions.buyoutPercent`.

**Важное следствие для агента 4:** история доступна только за последнюю неделю. Значит суточные данные надо забирать каждый день и копить у себя в `nm_daily` - ровно то, что и требует ТЗ (0.6). Без ежедневного накопления динамика за месяц не построится.

## 8. Остатки (агент 4)

**`POST https://seller-analytics-api.wildberries.ru/api/analytics/v1/stocks-report/wb-warehouses`**, категория **Аналитика**.

Тело: `nmIds[]`, `chrtIds[]`, `limit`, `offset`.
Ответ `data.items[]`: `nmId`, `chrtId`, `warehouseId`, `warehouseName`, `regionName`, `quantity` (доступно клиентам для добавления в корзину), `inWayToClient`, `inWayFromClient`.
Обновление раз в 30 минут. Одна строка = один размер на одном складе.
**Лимит: 3 запроса в минуту**, всплеск 1.

Поля `quantityFull` в новом методе **нет**. Ближайшее по смыслу: `quantity + inWayToClient + inWayFromClient`.

**Временное ограничение с 15.08.2026:** по складам в РФ детализация скрыта. `warehouseId` может приходить `-999999`, `warehouseName` и `regionName` - «Склад WB». Для расчёта «на сколько дней хватит остатка» это не мешает: нужна сумма по артикулу, а не разрез по складам.

## 9. Карточки товаров (шаблон себестоимости)

**`POST https://content-api.wildberries.ru/content/v2/get/cards/list`**, категория **Контент** (с 03.08.2026 токен «Продвижение» больше не подходит).

Тело:
```json
{"settings": {
  "sort": {"ascending": true},
  "cursor": {"limit": 100, "updatedAt": "", "nmID": 0},
  "filter": {"withPhoto": -1}
}}
```

Пагинация по алгоритму из документации: первый запрос с `cursor.limit`; скопировать `updatedAt` и `nmID` из `cursor` ответа в `cursor` следующего запроса; повторять, пока `total` в ответе не станет **меньше** `limit`.

Нужные поля карточки: **`nmID`** (именно так, с заглавными ID), `vendorCode`, `title`, `subjectName`.

**Лимит: 100 запросов в минуту**, интервал 600 мс, всплеск 5. Самый щедрый лимит из всех.

## 10. Лимиты и ошибки

**Алгоритм - token bucket.** Четыре параметра: Период, Лимит, Интервал (= Период / Лимит, рекомендуемая пауза между запросами), Всплеск (сколько можно послать подряд без пауз). Лимит считается **на стороне WB по токену**, а не по соединению. Лимиты Персонального и Сервисного токенов независимы.

**Заголовки ответа:**

| Заголовок | Когда | Что значит |
|---|---|---|
| `X-Ratelimit-Remaining` | во всех ответах, **кроме 429** | сколько запросов можно сделать прямо сейчас без пауз |
| `X-Ratelimit-Retry` | при 429 | через сколько **секунд** повторять |
| `X-Ratelimit-Limit` | при 429 | максимум всплеска, который восстановится |
| `X-Ratelimit-Reset` | при 429 | через сколько секунд всплеск восстановится |

Один запрос может считаться за несколько: для категории Маркетплейс ответ 4XX считается за 10 запросов, 409 - за 5 или 10. В теле ошибок 404 и 429 смотреть поле `detail`.

**401 против 403 - это разные вещи, и путать их нельзя:**

- **401** - проблема с самим токеном: отсутствует, передан с ошибкой, просрочен (180 дней), повреждён, отозван, сменился владелец кабинета. Это то, что в ТЗ: сообщить клиенту про токен, поставить модули на паузу.
- **403** - токен валиден, но не даёт прав: категория не совпадает с сервисом, метод недоступен для этого типа токена, токен только на чтение при попытке записи, Персональный токен используется в облачном сервисе, нет подписки Джем. **Это не повод ставить модули на паузу** - это повод сказать, какой категории не хватает.

Два формата ошибок: Problem Details (`application/problem+json`, с `requestId`) и API Error (`application/json`, с `code`).

## 11. Гео

**В официальной документации ничего про ограничение доступа к API по стране или IP нет.** Проверены страницы про лимиты, коды ошибок, FAQ и общая информация об API: слова «IP», «регион», «VPN», «блокировка по стране» в контексте доступа не встречаются. Лимиты привязаны к аккаунту продавца и типу токена, а не к адресу.

Что про географию есть, но это про другое: страна продавца влияет на состав методов (СПОТ только для Кыргызстана, номер ДТ обязателен для Армении). И с 15.08.2026 по складам в РФ временно скрыта детализация.

**Утверждения «нужен российский IP» в документации нет ни как подтверждения, ни как опровержения.** Практическая проверка остаётся за `/diag` с Bothost.

## 12. Что осталось НЕ ПОДТВЕРЖДЕНО

1. Поля payload `oid`, `sandbox`, `uid` - в документации их нет. Признак песочницы называется `t`.
2. Биты 0, 8, 14, 15 маски `s` - назначение неизвестно.
3. Числовой ID продавца в токене - есть только UUID `sid`.
4. Максимальная длина периода за один запрос в `sales-reports/detailed`.
5. Точные даты отключения `/adv/v2/fullstats` и `/api/v2/nm-report/detail` - методы отсутствуют, но запись об отключении не найдена.
6. Дата отключения `GET /api/v1/supplier/orders` и `/sales` - объявлено, дата не названа.
7. Формулы финансовой раскладки - в документации WB их нет вообще. Берём готовые поля.
8. Соответствие `delivery_rub → deliveryService` и `sa_name → vendorCode` - реконструкция по смыслу описаний.
9. Ограничение доступа к API по стране или IP.
