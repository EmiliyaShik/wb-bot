## Что должно заработать

Единственное место в проекте, которое знает про HTTP и токены WB. Умеет разобрать токен без единого запроса, сходить в любой нужный метод WB, не превысив лимит, и перевести любую ошибку в понятную боту и человеку.

Плюс админ-команда `/diag`, которая с боевого хоста проверяет связь со всеми серверами WB и объясняет каждый ответ простым языком. Это то, чем закрывается пункт 0.1 ТЗ.

**Все факты уже собраны и проверены по официальной документации** в `wb-api-facts.md`. Твоя задача - перенести их в `docs/wb-api.md` и реализовать, а не исследовать заново. Ничего, что помечено там «НЕ ПОДТВЕРЖДЕНО», в код не попадает.

## Критерии приёмки

- [ ] `docs/wb-api.md` написан по `wb-api-facts.md`: хосты, категории, пути, поля, лимиты, коды ошибок. Отмечено, какие методы из ТЗ отключены и чем заменены
- [ ] `verify_token(raw) -> TokenInfo` разбирает JWT БЕЗ сети и отдаёт: `sid` (UUID кабинета), `exp`, список категорий из маски `s`, признак «только на чтение» (бит 30), тип токена `acc`
- [ ] Биты категорий ровно как в документации: Контент 1, Аналитика 2, Статистика 5, Продвижение 6, Финансы 13, read-only 30
- [ ] Заголовок `Authorization: <токен>` без `Bearer`
- [ ] Обёртки для всех методов, которые понадобятся агентам: `sales-reports/detailed`, `sales-reports/list`, `adv/v1/promotion/count`, `adv/v3/fullstats`, `analytics/v3/sales-funnel/products/history`, `analytics/v1/stocks-report/wb-warehouses`, `content/v2/get/cards/list`, `common/v1/seller-info`, `/ping`. Больше никто обёрток не пишет
- [ ] Пагинация реализована там, где она есть: `rrdId` у отчёта, курсор `updatedAt`+`nmID` у карточек, `limit`/`offset` у аналитики
- [ ] Ограничитель частоты соблюдает лимит каждого метода из конфига, у отчёта о реализации отдельная медленная дорожка (1 запрос в минуту)
- [ ] Разбиение по ограничениям WB: `fullstats` не больше 50 кампаний и 31 дня за запрос
- [ ] 429 обрабатывается по заголовку `X-Ratelimit-Retry`; при его отсутствии растущая пауза. `X-Ratelimit-Remaining` учитывается, чтобы не упираться вслепую
- [ ] 401 и 403 это РАЗНЫЕ классы ошибок: `WBAuthError` (проблема с токеном) и `WBForbiddenError` (не хватает категории). Смешивать нельзя
- [ ] `get_wb_client(client_id)` достаёт и расшифровывает токен внутри себя. Агенты токен не видят и получить его не могут
- [ ] Каждый вызов пишет строку в `api_calls`: клиент, хост, метод, код ответа, время
- [ ] `/diag` (только владельцу) обходит 6 хостов методом `/ping` с паузами (лимит 3 запроса за 30 секунд на домен), печатает код по каждому и объясняет: 200 связь есть, 401 токен, 403 категория, таймаут похож на блокировку по адресу. По расписанию не запускается никогда
- [ ] Тесты идут через шов «транспорт»: подставной `httpx.AsyncClient` с записанными ответами. Покрыты 401, 403, 429 с заголовком и без, 500, таймаут, пагинация
- [ ] Ни один метод WB, который что-то меняет в кабинете, не реализован
