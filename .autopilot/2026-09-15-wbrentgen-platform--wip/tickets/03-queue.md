# 03 - Очередь фоновых задач и расписание

**Требования:** R36, R38, R41, R42, R43, R44, R166
**Blocked by:** 01
**Зона:** `core/queue.py` · `core/scheduler.py`
**Волна:** 2
**Status:** ready

## Что должно заработать

Любая тяжёлая работа ставится в очередь, клиент сразу получает «принято», результат приходит отдельно. Очередь лежит в базе, а не в памяти, поэтому перезапуск контейнера на Bothost ничего не теряет.

Плюс расписание: ежедневные задачи утром по Москве, еженедельные - когда у WB появился новый финотчёт, а не по будильнику.

Ты делаешь только механику. Сами задачи регистрируют их владельцы в своих тасках.

## Из брифа, дословно

> «Тяжёлые выгрузки идут в фоне с соблюдением лимитов WB API ... Клиенту сразу приходит «принято, пришлю, когда будет готово», потом результат.»
>
> «WB недоступен: повторить позже. После нескольких неудач сообщить клиенту понятным текстом и записать ошибку для владельца.»
>
> «Ежедневные отчёты утром, еженедельные после появления нового финотчёта WB. Время по умолчанию московское.»

## Разделы спецификации

«Очередь фоновых задач», истории G1, G2, G7, G8, G9

## Критерии приёмки

- [ ] `enqueue(client_id, kind, payload)` кладёт задачу в таблицу `tasks` и сразу возвращает управление
- [ ] Воркер берёт задачи по `next_run_at`, по одной, не нарушая лимитов `core.wbapi`
- [ ] Перезапуск процесса не теряет задачи: при старте всё, что осталось в состоянии `running`, возвращается в `pending`
- [ ] Повтор при `WBUnavailable` и `WBRateLimited` с растущей паузой; число попыток из конфига
- [ ] После исчерпания попыток: клиенту понятный текст без кодов ошибок, владельцу запись в журнал уровня error, задача в состоянии `failed`
- [ ] `WBAuthError` (401) попытки не тратит: задача отменяется сразу, вызывается обработчик про токен
- [ ] `WBForbiddenError` (403) тоже не повод повторять: задача отменяется, клиенту говорится, какой категории не хватает
- [ ] Регистрация задач расписания: `register_daily(name, fn)` и `register_weekly(name, fn)`, время и часовой пояс из конфига (по умолчанию 09:00 Europe/Moscow)
- [ ] Еженедельный запуск привязан к появлению нового финотчёта WB, а не к фиксированному дню недели
- [ ] Бот не падает ни при одной из этих ошибок
- [ ] Тесты на шве «база»: постановка, повтор, исчерпание попыток, восстановление после рестарта
