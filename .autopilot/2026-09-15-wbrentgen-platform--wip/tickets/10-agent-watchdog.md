## Разделы спецификации

Истории E6-E9, «Конфиг» (секция alerts)

## Критерии приёмки

- [ ] Ни одного обращения к `core.wbapi`. Тест это доказывает: подставной транспорт не получает ни одного вызова
- [ ] Считаются пять показателей за неделю: фактическая комиссия %, эквайринг %, средний СПП %, доля логистики в выручке, доля хранения в выручке
- [ ] Фактическая комиссия - реально удержанная, а не тарифная
- [ ] Сравнение со средним за 4 предыдущие недели (число недель из конфига)
- [ ] Пороги из конфига, по умолчанию: эквайринг +0,5 п.п., комиссия +2 п.п., СПП -5 п.п., логистика +2 п.п., хранение +2 п.п.
- [ ] Алерт по шаблону: что изменилось, с чего на что, на сколько пунктов, сколько рублей это стоило за неделю при текущей выручке
- [ ] Алерты уходят в еженедельной рассылке, когда появился новый финотчёт
- [ ] Меньше 5 недель данных: алертов нет, вместо них честное «пока мало данных для сравнения, нужно N недель». Не падать
- [ ] `/dynamics` показывает таблицу показателей по неделям за выбранный период
- [ ] Прямые тесты расчёта на подготовленных цифрах: порог не пройден, порог пройден, недостаточно истории, нулевая выручка (без деления на ноль)
