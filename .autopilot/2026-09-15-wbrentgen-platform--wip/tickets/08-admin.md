## Что должно заработать

Всё, что нужно владельцу и не нужно клиенту. Одна команда показывает бизнес целиком, другая готовит реестр для актов, третья показывает, что упало, и даёт это перезапустить.

Плюс ограничение частоты команд, чтобы один человек не мог задолбать бота.

## Из брифа, дословно

> «Админ-команда /stats: активные клиенты по модулям, выручка за месяц, расходы, маржа по клиентам, выставленные и неоплаченные счета.»
>
> «выдать доступ вручную с указанием способа оплаты (счёт, карта, другое) и номера платежа; отменить доступ (возврат). Всё пишется в журнал.»
>
> «Раз в месяц (и по команде /acts) бот присылает владельцу Excel оплаченных счетов для подготовки актов: номер, дата, ИНН, название клиента, модуль, период, сумма.»
>
> «Видит клиентов, счета, оплаты, ошибки, расходы ... перезапускает задачи.»
>
> «Ограничение частоты команд на одного клиента.»

Истории H1, H1a, H1b, H4, H5, D8, D10

## Критерии приёмки

- [ ] Все команды здесь доступны ТОЛЬКО владельцу по `ADMIN_TELEGRAM_IDS`. Чужой вызов получает тот же ответ, что и несуществующая команда. Тест это доказывает
- [ ] `/stats`: активные клиенты по модулям, выручка за месяц по оплаченным счетам, расходы (вызовы WB по методам из `api_calls`), маржа по клиентам, выставленные и неоплаченные счета
- [ ] `/acts` отдаёт Excel оплаченных счетов за месяц: номер, дата, ИНН, название клиента, модуль, период, сумма. То же самое приходит автоматически раз в месяц
- [ ] `/grant` выдаёт доступ вручную: клиент, модуль, период, способ оплаты (счёт, карта, другое), номер платежа. Идёт через `grant_access`, а не мимо
- [ ] `/revoke` отменяет доступ (возврат) и пишет причину
- [ ] Каждая выдача и отмена пишется в `access_log`: кто, кому, что, когда, каким способом, по какому платежу
- [ ] `/tasks` показывает задачи в работе и упавшие: клиент по внутреннему id, тип, число попыток, текст ошибки. Плюс последние записи журнала уровня error
- [ ] У каждой упавшей задачи кнопка «Перезапустить»: счётчик попыток обнуляется, задача возвращается в очередь, действие пишется в журнал
- [ ] Ограничение частоты команд на клиента, параметры из конфига. Превышение - вежливое «подожди немного», а не молчание
- [ ] В журнал и в ответы админки не попадают ни токены, ни реквизиты, ни персональные данные клиентов
- [ ] Тесты на шве «база», включая проверку, что не-владелец не видит ничего
