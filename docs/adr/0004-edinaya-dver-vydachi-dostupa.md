# 0004. Единственная дверь для выдачи доступа и идемпотентность по номеру платежа

## Контекст

Доступ к модулю включается четырьмя разными путями: оплаченный счёт, пробный период, ручная выдача владельцем, а когда-нибудь и Tribute (отложен). Заказчик сформулировал требование прямо (R64, R65): любой способ оплаты в итоге вызывает одну функцию, повторный вызов с тем же платежом ничего не продлевает.

## Решение

Доступ включается только вызовом `grant_access(client_id, module, days, payment_ref, method, actor)`. `payment_ref` уникален: повтор с тем же значением не продлевает ничего, возвращает уже выданный доступ и пишет в журнал строку «дубль». Окончание доступа, наоборот, идёт не по платежу, а по состоянию: `active` → `grace` 3 дня → `off`, отдельно `paused` при 401.

## Почему

Дубль здесь стоит денег. Владелец нажимает «Оплачен», не видит подтверждения, нажимает ещё раз - и клиент получает два месяца за один платёж. Ключ идемпотентности должен быть тем, что уникально у события оплаты, то есть номером платежа, а не временем нажатия и не парой клиент-модуль.

Рассмотрели и отвергли:

- **Разрешить каждому пути включать доступ самостоятельно.** Четыре реализации одного правила про льготный период, паузу и продление. Разъезжаются они не сразу, а на пятом сценарии, и первым это замечает клиент.
- **Идемпотентность по паре «клиент плюс модуль».** Сломала бы честное продление: второй счёт того же клиента на тот же модуль - это нормальная покупка, а не дубль.
- **Идемпотентность по времени («не чаще раза в минуту»).** Защищает от двойного клика и не защищает от повторного нажатия на следующий день, которое как раз и происходит, когда владелец сверяет выписку второй раз.
- **Сделать отмену тоже идемпотентной по номеру платежа.** Отмена не привязана к платежу: доступ гаснет по истечении срока, по 401, по возврату денег. Ключом здесь может быть только текущее состояние доступа, иначе возврат по счёту, которого уже нет, ничего не выключит.

## Последствия

- Любой новый способ оплаты обязан принести с собой `payment_ref`. Для ручной выдачи это значит, что владелец должен его вписать, даже когда «просто включи другу»: без номера нет защиты от дубля.
- Журнал становится единственным местом, где видно, что дубль был. Молчаливая идемпотентность без записи «дубль» превратилась бы в исчезающие платежи.
- Пауза по 401 сдвигает срок на свою длительность. Это отдельная арифметика поверх состояний, и она обязана переживать перезапуск: `paused_since` хранится в базе.
- Льготные 3 дня означают, что `has_access` возвращает «да» и после истечения оплаты. Любой отчёт о выручке, считающий активных по `until`, разойдётся с тем, что видит клиент.
