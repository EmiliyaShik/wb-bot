# Автосверка поступлений через API Сбера: что понадобится

Разведка по открытым источникам на 16.09.2026. Сама автосверка не делается,
это отложенный пункт ТЗ. Здесь собрано то, что нужно знать, когда к нему
вернёмся.

Банковские API меняются часто, а старые статьи врут. Перед началом работ
факты из этого файла стоит перепроверить: даже официальный старый портал
документации Сбера (developer.sberbank.ru) сейчас отдаёт просроченный
сертификат, часть сведений там уже неактуальна.

---

## Вывод в первых строках

При десятке счетов в месяц прямой API Сбера не окупается. Подключение,
сертификат с ежегодным перевыпуском, отдельный постоянно работающий сервер,
ручное продление доступа примерно раз в полгода и непрозрачный тариф стоят
дороже, чем пять минут в день на просмотр выписки.

Разумный порядок: пока оставить ручную кнопку «Оплачен». Когда счетов станет
50-100 в месяц, вернуться к вопросу, и начинать не с живого API, а с выгрузки
файла в формате 1С или с перехода на оплату по СБП-ссылке, где подтверждение
об оплате приходит само и сверять выписку не нужно вообще.

Дальше подробности для того, кто решил браться.

---

## 1. API у Сбера есть

Называется **Sber API** (раньше SberBusiness API, ещё раньше Fintech API).
Документация открытая: developers.sber.ru, раздел sber-api. Доступен и
юрлицам, и ИП.

Для выписки есть отдельная группа методов:

- полная выписка за дату,
- «инкрементальная» выписка за текущий день, только новые операции,
- данные одной операции,
- выгрузка файла выписки в формате для внешних систем.

---

## 2. Что нужно, чтобы подключить

1. Зайти в интернет-банк СберБизнес, раздел «Все продукты и услуги», найти
   SberBusiness API, заполнить заявление и подписать электронной подписью.
   Сбер сделал это самообслуживанием, раньше шло через менеджера.
2. После заявления сразу дают доступ к тестовому стенду и личному кабинету
   Sber API.
3. В личном кабинете выпустить TLS-сертификат, можно сгенерировать
   автоматически. Срок действия 12 месяцев, потом перевыпуск руками.
   Сертификат привязан к одному приложению.
4. Получить client_id и client_secret приложения. Секрет периодически надо
   обновлять.
5. Один раз авторизоваться через браузер (стандарт OAuth: владелец входит под
   собой и даёт согласие). Дальше программа работает в фоне по refresh-токену.
   Токен доступа живёт 60 минут, refresh-токен 180 дней. То есть примерно раз
   в полгода владельцу придётся заново подтвердить доступ руками.
6. Запросить право (scope) `GET_STATEMENT_ACCOUNT`, получение выписки по
   счёту. Для чтения выписки электронная подпись сотрудника не нужна, она
   нужна только чтобы отправлять платежи.
7. Соединение идёт по mTLS: и банк, и наша программа предъявляют сертификаты.
   Для бота это значит, что он должен жить на постоянном сервере, где лежит
   сертификат. С домашнего ноутбука по настроению это не работает.

### Про деньги честно

Сбер в своих материалах пишет, что подключение бесплатное и часть сервисов
включается самостоятельно. При этом в личном кабинете Sber API есть график
«статистика и стоимость запросов по действующей тарифной сетке», то есть
тарификация по числу запросов существует. Публичного прайса найти не удалось,
цифру назвать нельзя. Это надо спросить у своего менеджера или в поддержке:
supportdbo2@sberbank.ru, 8 800 555-57-77.

Отдельно: цифра 69 900 ₽, которая попадается в сети, это цена внедрения у
стороннего интегратора, а не тариф банка. Не путать.

## 3. Формат 1С и выгрузка файлом

Да, это реально. У Сбера есть метод «запрос файла выписки в формате для
экспорта»: программа просит файл, получает номер задачи, потом скачивает
готовый файл. В обзорной документации как форматы экспорта названы **1C** и
**MT940**.

Точное имя формата (тот самый `1CClientBankExchange`) в публичной документации
явно не прописано, это стоит уточнить в поддержке. Не подтверждено.

Отдельно есть **1С:ДиректБанк**: если есть 1С, выписка тянется в неё почти в
один клик, без программирования. Но это выгрузка в 1С, а не в бота, боту
оттуда данные ещё надо как-то забрать.

Про «открытые банковские интерфейсы» (Open Banking по стандарту ЦБ): ничего
работающего и публично доступного для ИП у Сбера найти не удалось.

---

## 4. Что приходит в выписке

Всё, что нужно для сверки, там есть. В операции возвращаются:

| Поле | Что это |
|---|---|
| `paymentPurpose` | назначение платежа целиком, номер нашего счёта оттуда вытащить можно |
| `payerName` | наименование плательщика |
| `payerInn` | ИНН плательщика |
| `amount` | сумма и валюта |
| `operationDate` | дата и время операции |
| идентификатор операции | по нему можно не засчитать один платёж дважды |

Глубина хранения: текущий год плюс 5 предыдущих лет.

Это главное подтверждение для нашей схемы: бот кладёт номер счёта в назначение
платежа, и назначение приходит целиком, значит сверка по номеру возможна.

## 5. Ограничения

- Опрос, а не подписка, работает нормально: есть метод «выписка за текущий
  день», можно дёргать его раз в 10-15 минут.
- Лимит на частоту запросов есть, при превышении приходит ошибка 429, но
  конкретные цифры Сбер публично не называет. Не подтверждено.
- Вебхуки (когда банк сам стучится к нам при событии) в документации
  упомянуты, нужен постоянный внешний адрес с HTTPS и отдельная заявка.
  Детали по событию «поступили деньги» подтвердить не удалось: старый портал
  документации отдаёт просроченный сертификат.
- Задержка появления поступления в выписке нигде не описана. По практике
  безналичные приходят в течение рабочего дня, ночью и в выходные движения
  нет. Мгновенной реакции «оплатил и через минуту доступ» не будет в любом
  случае, это ограничение банковского перевода, а не API.

## 6. Альтернативы, если прямой API окажется тяжёлым

- **Сервисы учёта с автозагрузкой выписки**, например Seeneco: сами
  подключаются к Сберу и отдают операции по своему API. Цена от 1 300 ₽ в
  месяц. Минус прямой: мы отдаём стороннему сервису доступ к своему
  расчётному счёту на чтение.
- **1С:ДиректБанк**, если 1С уже есть: выписка приезжает без API банка, но
  дальше её всё равно надо передавать боту.
- **Сменить сам способ оплаты**: приём через СБП по ссылке или через
  платёжный сервис (ЮKassa, Яндекс Пэй, CloudPayments). Тогда уведомление об
  оплате приходит мгновенно и автоматически, сверять выписку не надо вообще.
  Минус: комиссия с каждого платежа и другой документооборот, счёт от ИП по
  реквизитам это не заменит, если клиенты платят как юрлица.
