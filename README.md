# WB Bot — анализ карточек товаров Wildberries

Telegram-бот, который по артикулу товара возвращает **название, цену, рейтинг и количество отзывов** с Wildberries.

## Возможности

- Принимает артикул числом или ссылкой на товар
- Показывает название, бренд, продавца
- Актуальную цену со скидкой и старую цену
- Рейтинг и количество отзывов
- Характеристики и описание товара (с CDN Wildberries)
- Последние отзывы покупателей
- Ссылку на карточку товара

## Установка

1. Установите зависимости:

   ```powershell
   pip install -r requirements.txt
   ```

2. Получите токен бота у [@BotFather](https://t.me/BotFather) в Telegram.

3. Создайте файл `.env` на основе `.env.example` и вставьте туда токен:

   ```
   TELEGRAM_BOT_TOKEN=123456:ABC-DEF...
   ```

## Запуск

```powershell
python bot.py
```

Затем напишите боту в Telegram артикул товара, например `179323396`.

## Структура

- `bot.py` — логика Telegram-бота (команды, обработка сообщений, форматирование)
- `wb_api.py` — клиент публичного API Wildberries (получение карточки товара)
- `requirements.txt` — зависимости
- `Procfile` — команда запуска для хостинга (`worker: python bot.py`)
- `.python-version` — версия Python для сборки (3.13)

## Как это работает

Бот собирает карточку из трёх публичных источников Wildberries:

- `card.wb.ru/cards/v4/detail` — название, бренд, продавец, цена, рейтинг, `root`.
  Цены приходят в копейках и переводятся в рубли (парсинг с запасным вариантом);
- `feedbacks{1,2}.wb.ru/feedbacks/v2/{root}` — отзывы (ответ в gzip);
- `basket-XX.wbbasket.ru/.../card.json` — описание и характеристики.

Отзывы и карточка с CDN подтягиваются best-effort: если источник недоступен,
бот всё равно ответит базовыми данными. Официального стабильного API у WB нет —
формат ответа может меняться.

> **Гео-блокировка.** `card.wb.ru` отвечает только на запросы с российских IP;
> с зарубежного адреса приходит `403`. Разворачивайте бот на хостинге в РФ/СНГ
> либо включите прокси (см. переменные окружения ниже).

## Деплой на хостинг

Бот работает по long-polling (не веб-сервер), поэтому запускается как
**worker**-процесс, а не web.

1. Убедитесь, что `.env` **не** попадёт в git (он уже в `.gitignore`).
2. Залейте проект в git-репозиторий и подключите его к хостингу
   (Railway, Render, Heroku, VPS и т.п.).
3. Задайте переменные окружения на стороне хостинга (список ниже) —
   **не** через файл `.env`.
4. Команда запуска: `python bot.py` (её же берёт `Procfile`).

### Переменные окружения

| Переменная          | Обязательна | Значение / пример                                   |
|---------------------|-------------|-----------------------------------------------------|
| `TELEGRAM_BOT_TOKEN`| **да**      | токен от [@BotFather](https://t.me/BotFather)        |
| `WB_PROXY_ENABLED`  | нет         | `1`, чтобы включить прокси к WB (по умолчанию выкл.) |
| `WB_PROXY`          | нет*        | `http://user:pass@host:port` или `socks5://host:port`|

\* обязательна только если `WB_PROXY_ENABLED=1`. Для `socks5`-прокси добавьте
зависимость: `pip install "httpx[socks]"`.

Если хостинг находится в РФ/СНГ, прокси не нужен — оставьте `WB_PROXY_ENABLED`
выключенным.
