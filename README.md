# WBРентген

Telegram-бот аналитики для селлеров Wildberries: [@WBRentgen\_bot](https://t.me/WBRentgen_bot)

Селлер подключает свой кабинет WB личным токеном только на чтение и платит помодульно. Бот сам ходит в WB Seller API, копит данные и присылает готовые разборы текстом и книгами Excel. Ничего в кабинете клиента бот не меняет: методов записи в коде нет ни одного, и это проверяется тестом.

## Модули

| Модуль | Цена | Что делает |
|---|---|---|
| `finance` | 990 ₽/мес | Финансовая раскладка по неделям: комиссия, логистика, хранение, приёмка, штрафы, удержания. Сводка в сообщении, подробности книгой Excel. Сюда же входят сторож скрытых расходов и прибыль по каждому артикулу |
| `rnp` | 590 ₽/мес | План-факт: ежедневный отчёт «идём по плану или нет» и прогноз на конец месяца |
| `ads` | 1290 ₽/мес | Реклама: расход, заказы, цена заказа и ДРР по каждой кампании и по дням, рядом с вашей целью по ДРР |
| `funnel` | 490 ₽/мес | Воронка: заход в карточку, корзина, заказ, выкуп по каждому товару и шаг, на котором покупатели стали теряться чаще |
| `all` | 2490 ₽/мес | Пакет «Всё сразу»: все модули одной подпиской. По отдельности те же четыре стоили бы 3360 ₽ |

Пробный период: один модуль на выбор, 7 дней, один раз на кабинет. Пакет пробно не выдаётся.

Кроме платного есть бесплатная диагностика: разовый разбор кабинета, чтобы селлер увидел, где деньги утекают.

## Команды

Клиенту: `/start`, `/help`, `/connect`, `/disconnect`, `/tariffs`, `/modules`, `/trial`, `/finance`, `/dynamics`, `/profit`, `/costs`, `/plan`, `/rnp`, `/ads`, `/funnel`, `/diagnostic`, `/settings`, `/paysupport`.

Набирать их руками необязательно: команды заявлены в меню Telegram, а под приветствием и под экраном отчётов есть кнопки.

Владельцу: `/stats`, `/acts`, `/grant`, `/revoke`, `/tasks`, `/diag`. Постороннему эти команды не отвечают ничем, даже отказом: иначе перебор команд выдал бы список админки любому.

## Запуск

Нужен Python 3.13.

```bash
pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env` и заполните. Обязательны две переменные: `TELEGRAM_BOT_TOKEN` (у [@BotFather](https://t.me/BotFather)) и `ENCRYPTION_KEY` - без него бот работает, но токены кабинетов принимать не будет. Ключ генерируется командой:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Остальные переменные и что будет без каждой из них описано прямо в `.env.example`.

```bash
python bot.py
```

Бот работает на long polling, вебхук не нужен. На хостинге запускается через `Procfile`: `worker: python bot.py`.

## Тесты

```bash
python -m pytest -q
```

Сети в тестах нет: транспорт к Wildberries подставляется фейком. Кроме обычных тестов есть сторожа, которые падают при нарушении правил проекта: длинные тире в текстах бота, отключённые или меняющие кабинет методы WB в коде, неидемпотентный оператор в схеме базы, сообщение с разметкой в обход общего экранирования.

## Безопасность

Репозиторий публичный, поэтому здесь нет и не должно быть ни секретов, ни реквизитов, ни данных клиентов.

- Секреты только в переменных окружения. `.env` в `.gitignore`, рядом лежит `.env.example` с пустыми значениями.
- Токены кабинетов шифруются (Fernet), ключ только в окружении.
- База, счета и выгрузки в `.gitignore` и не коммитятся никогда.
- В журнал пишутся события, а не токены, реквизиты и данные клиентов: `core.audit.redact` вычищает секреты, JWT и длинные номера.
- Один клиент не видит данные другого: доступ к данным идёт только через `repo(client_id)`.
- Чужой текст (с витрины WB, из справочника ИНН, из команд) экранируется на границе подстановки, единственным инструментом на весь бот.
- Лимиты WB API соблюдаются с запасом: лучше медленнее, чем блокировка токена.

## Как устроено

```
bot.py            точка входа
bot/              телеграм-поверхность, по файлу на команду
agents/           разборы и рассылки: finance, watchdog, profit, rnp, ads, funnel, diagnostic, lifecycle
core/             конфиг, база, очередь, расписание, доступ, журнал, счета
core/wbapi/       единственное место с HTTP и токенами WB
legacy/           старое поведение: артикул или ссылка -> карточка товара
migrations/       схема базы целиком, одним файлом
docs/             что в WB Seller API живо и чем заменено отключённое, плюс решения в docs/adr/
config.toml       цены, периоды, пороги, расписание; секретов нет
```

Отчёты строятся по своей базе, а не живыми запросами в кабинет: в Wildberries ходят только ночные сборщики, и ходят они через очередь с соблюдением лимитов. Поэтому у бота есть история там, где сам Wildberries её уже не отдаёт: суточную воронку он хранит неделю, а статистику удалённой рекламной кампании не хранит вовсе.

Подробности для разработки в `CLAUDE.md`, решения и их причины в `docs/adr/`.
