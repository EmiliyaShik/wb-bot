# WBРентген (@WBRentgen_bot)

Telegram-бот для селлеров Wildberries: подключаешь свой кабинет по токену WB и платишь только за нужные модули аналитики (финансы, план-факт, реклама, воронка). Бот сам собирает данные из WB API и присылает готовые разборы и Excel.

## Команды

| Команда | Что делает |
|---------|------------|
| `pip install -r requirements.txt` | Установить зависимости |
| `python bot.py` | Запустить локально (нужен `.env` с `TELEGRAM_BOT_TOKEN`) |
| `pytest` | Прогнать тесты |

## Где секреты

Только в переменных окружения: локально - файл `.env` (он в `.gitignore`), на хостинге Bothost - в настройках окружения. Шаблон с заглушками - `.env.example`. Репозиторий публичный, поэтому в коде, в истории коммитов и в логах не должно быть ни токенов, ни реквизитов ИП, ни данных клиентов.

## Как здесь работает Autopilot

Сборка ведётся навыком `/autopilot`. Требования, спецификация и таски - в `.autopilot/`.
Прогресс - `.autopilot/dashboard.html`. Правило: требование из `manifest.md`
может снять только пользователь.

Если работа продолжается - скажи «продолжи автопилот»: состояние поднимется
из `.autopilot/state.js`, переспрашивать ничего не нужно.

Зависимость `tzdata` нужна не для красоты: на Windows системной базы часовых
поясов нет, и без неё `ZoneInfo("Europe/Moscow")` падает, а расписание уезжает
на UTC. Не выкидывайте её из `requirements.txt`.

## Финансовая раскладка: поля WB и формулы

Источник: `POST https://finance-api.wildberries.ru/api/finance/v1/sales-reports/detailed`,
категория токена «Финансы», `period = weekly`. Метод из ТЗ
(`GET /api/v5/supplier/reportDetailByPeriod`) Wildberries отключил 15.07.2026,
старых имён полей в snake_case больше не существует. Лимит **1 запрос в минуту**,
самый жёсткий в проекте: длинные периоды выгружаются страницами по `rrdId` и
идут долго, поэтому `/finance` работает только через очередь.

Сверка: `POST /api/finance/v1/sales-reports/list` отдаёт готовые суммы по отчёту.

Параметр `fields` в запрос **не передаётся намеренно**: тогда WB отдаёт строку
целиком, и в колонке `fin_rows.raw` лежит вся строка, как обещано агентам 10
и 11. Таблица ниже это то, на чём стоит раскладка, а не фильтр запроса.

Неполная выгрузка помечается: если пагинация упёрлась в потолок страниц,
неделя записывается как неполная и клиент видит предупреждение. Неделя без
агрегата WB это «сверка не выполнена», а не «сошлось».

**Поля ответа, которые использует бот**

| Поле WB | Что значит | Куда идёт |
|---|---|---|
| `reportId` | номер отчёта, он же неделя | ключ `fin_weeks`, `fin_rows.report_id` |
| `rrdId` | номер строки и курсор пагинации | ключ строки в `fin_rows` |
| `dateFrom`, `dateTo` | границы отчётной недели | `fin_weeks.date_from`, `.date_to` |
| `docTypeName` | тип документа: продажа или возврат | делит продажи и возвраты |
| `retailAmount` | «Wildberries реализовал товар» | продажи и возвраты |
| `retailPriceWithDisc` | цена со скидкой | вес для средневзвешенных процентов |
| `forPay` | **к перечислению продавцу** | `for_pay_kop` |
| `vw` | вознаграждение Wildberries без НДС | комиссия в рублях |
| `commissionPercent`, `kvw` | размер кВВ и итоговый кВВ, % | комиссия в процентах |
| `acquiringFee`, `acquiringPercent` | эквайринг в рублях и процентах | как есть |
| `spp` | платформенные скидки, % | это и есть СПП |
| `deliveryService` | услуги по доставке покупателю | логистика |
| `paidStorage` | платное хранение | хранение |
| `paidAcceptance` | операции на приёмке | приёмка |
| `penalty` | общая сумма штрафов | штрафы |
| `deduction` | удержания, в том числе за рекламу | прочие удержания |
| `additionalPayment` | корректировка вознаграждения WB | отдельной статьёй |
| `nmId`, `vendorCode`, `subjectName` | артикул WB, артикул продавца, предмет | лист «По артикулам» |
| `quantity` | количество штук | продано и возвращено |

**Формулы**

Проценты не пересчитываются: у Wildberries есть готовые поля, и свой пересчёт
гарантированно разошёлся бы с личным кабинетом (R165).

- Продажи = сумма `retailAmount` по строкам, где `docTypeName` не «Возврат».
- Возвраты = сумма `retailAmount` по строкам возврата, отдельной статьёй.
- К перечислению = сумма `forPay` по всем строкам недели, включая возвраты.
- Комиссия WB, ₽ = сумма `vw`.
- Комиссия WB, % = средневзвешенное готового `commissionPercent`, вес `retailPriceWithDisc`. Проверка руками: `vw / retailPriceWithDisc * 100`.
- кВВ итоговый, % = средневзвешенное готового `kvw`.
- Эквайринг, ₽ = сумма `acquiringFee`; %  = средневзвешенное `acquiringPercent`. Проверка: `acquiringFee / retailPriceWithDisc * 100`.
- СПП, % = средневзвешенное готового `spp`.
- Логистика, хранение, приёмка, штрафы, прочие удержания, корректировка = суммы `deliveryService`, `paidStorage`, `paidAcceptance`, `penalty`, `deduction`, `additionalPayment`.
- Доля логистики, % = сумма `deliveryService` / сумма `retailAmount` * 100. Доля хранения считается так же по `paidStorage`. **Это наши определения, в документации WB таких формул нет.**
- Свод в месяц: неделя относится к месяцу, в котором она началась (`dateFrom`).
- Сверка: наша сумма по строкам минус готовая из `sales-reports/list` (`forPaySum`, `retailAmountSum`, `deliveryServiceSum`, `paidStorageSum`, `paidAcceptanceSum`, `penaltySum`, `deductionSum`). Расхождение больше рубля показывается клиенту, а не прячется.

Деньги в базе лежат целыми копейками (колонки с суффиксом `_kop`), в расчётах
`Decimal`, `float` для денег не используется нигде.
